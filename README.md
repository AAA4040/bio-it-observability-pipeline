# Bio-IT Observability Pipeline

A production-ready, event-driven log monitoring and observability pipeline designed to capture, parse, and store critical system logs generated by medical and biological software ecosystems. The architecture ensures zero log data loss, real-time persistence, and instant production alerts.

---

## 🏗️ System Architecture

The pipeline is built with modularity and low footprint in mind, leveraging core Linux utilities, containerized environments, and relational persistence layers:

1. **Log Streamer (Source):** Monitors active software application logs continuously using non-blocking, event-driven I/O.
2. **Parser & Sanitizer (Engine):** A robust script that intercepts raw streams, sanitizes data via rigorous regex parsing to eliminate security vulnerabilities, and structures raw strings into relational metrics.
3. **Database (Persistence):** A containerized PostgreSQL instance utilizing Docker Volumes for permanent data persistence and reliability.
4. **Alerting System (Notification):** Connects to external APIs (Telegram API) to dispatch immediate, high-priority notifications regarding system failures or operational anomalies.

## ⚡ Engineering Challenges & Solutions

### 1. Eliminating High CPU Overheads
* **The Problem:** Traditional polling methods used aggressive `while` loops to check for log updates, resulting in unacceptable idle CPU spikes and resource exhaustion.
* **The Engineering Fix:** Refactored the core ingestion layer to use an event-driven mechanism via `tail -F`. This shifted the system to an asynchronous model, dropping idle CPU utilization to **0%**.

### 2. Handling OS Log-Rotations Safely
* **The Problem:** Standard log monitoring fails or breaks tracking when the operating system triggers log-rotations (truncating or swapping active files), causing critical gaps and data loss.
* **The Engineering Fix:** Implemented `tail` with the file descriptor tracking flag (`-F` rather than `-f`), ensuring that the execution thread seamlessly rebinds to the newly created log files instantly without script interruption.

### 3. Mitigating SQL Injection (SQLi) Threats
* **The Problem:** Piping unescaped raw string inputs straight from log files into database queries poses severe SQL Injection vulnerabilities if malicious payloads infect the log streams.
* **The Engineering Fix:** Integrated strict data-sanitization patterns. All incoming data streams pass through strict Regex validation filters to strip, escape, and bind variables prior to interacting with the PostgreSQL runtime.

## 🚀 Deployment & Installation

### Prerequisites
Make sure you have Docker and Docker Compose installed on your host machine.

### 1. Clone the Repository
```bash
git clone [https://github.com/AAA4040/bio-it-observability-pipeline.git](https://github.com/AAA4040/bio-it-observability-pipeline.git)
cd bio-it-observability-pipeline
```

### 2. Configuration Env Variables
Create a .env file in the root directory to store your credentials securely:
```
DB_NAME=bio_observability_db
DB_USER=postgres_user
DB_PASSWORD=your_secure_password
TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_CHAT_ID=your_chat_id
```
### 3. Spin Up the Architecture
Launch the containerized environment using Docker Compose:

```Bash
docker-compose up -d
```
### 4. Verify System Logs
To inspect if the core services and parsing engines are running properly:

```Bash
docker-compose logs -f
```

## 📊 Database Schema Design
The structured database consists of relational models engineered to hold operational data efficiently:

* **`id`(SERIAL, Primary Key)**

* **`timestamp` (TIMESTAMP WITH TIME ZONE)**

* **`log_level` (VARCHAR - INFO, WARNING, ERROR, CRITICAL)**

* **`source_module` (VARCHAR)**

* **`message` (TEXT - Fully sanitized data stream)**
